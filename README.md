# budget

一个零依赖的终端记账 App：**Rich TUI + SQLite**。

## 跑起来

```bash
./budget            # 或 python3 tui.py
```

依赖：Python 3.9+ 和 `rich`（`pip install rich`）。数据库落在 `data/budget.db`，单文件，随时可备份。

## 三个 Tab

用 `Tab` 循环切换。

**1 输入** — 只有一行命令提示，屏幕上没有别的干扰。按任意键开始输入：

```
35 午饭 #餐饮 @同事              记一笔支出（默认今天）
昨天 42 打车 #交通               指定日期，也支持 前天 / -3d
b 50 每周三 12:00 咖啡 #餐饮     建预算，周期自己定
b 1200 每月1号 房租 #生活        月度预算
b 30 每2天 早餐                  间隔型预算
p 咖啡 18 #餐饮 12:00            建行动模板
tag 12 +报销 -待定               改标签
?                                帮助
```

周期写法：`每天` / `每周三` / `每周一,三` / `每2天` / `每3周` / `每月1号` / `每年3月1号`
时间写法：`12:00` / `中午` / `晚上`（不写就用当前时间语义，不占位）

**2 总览** — 看某一天的支出与预算计划，`← →` 换日期，`t` 回今天，`m` 进月度报表。

**3 浏览** — 一次只看一天，在这里细看和修改：
`↑ ↓` 选中 · `e` 改金额 · `g` 改标签 · `d` 删除 · `p` 建行动模板 · `← →` 换日期

## 月度报表

总览页按 `m`。对每个预算给出：周期、当月触发次数、计划金额、实际金额、进度条。
报表数字的匹配规则是刻意收紧的：

- 记录显式挂到某个预算 → 一定计入
- 否则只有当预算声明了 `#分类` 或 `@标签`，且记录落在触发日，才自动计入
- 两者都没有的预算（比如「理发 ¥200」）**只做计划，不吞任何消费**

这条规则是为了让"实际 vs 计划"可信——宁可漏算，不可错算。

## 结构

| 文件 | 职责 |
|---|---|
| `tui.py` | Rich 渲染 + 按键循环，纯展示层 |
| `actions.py` | 用例层，唯一写数据的地方（TUI 和未来任何传输层共用） |
| `db.py` | SQLite schema 与 CRUD |
| `parser.py` | 命令语言解析 |
| `recurrence.py` | 周期规则引擎 + 月报聚合 |

`actions.py` 是刻意独立的一层：TUI 只是它的一种前端。想加 HTTP / CLI / Raycast 脚本，直接调 `actions.run_command()` 即可，不用碰数据逻辑。
